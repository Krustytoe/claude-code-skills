# claude-code-skills

Claude Code plugin marketplace (`krustytoe-skills`) that ships the `sre-toolkit` plugin: skills for Terraform change review, Prometheus alert authoring, incident triage, and AWS GovCloud readiness review. Skills follow inspect → validate → plan → approve → apply → record, and are read-only by default.

## Layout

- `.claude-plugin/marketplace.json` — marketplace manifest; lists plugins and their `source` paths.
- `plugins/sre-toolkit/.claude-plugin/plugin.json` — plugin manifest. Its `version` is bumped by release-please; do not edit it by hand.
- `plugins/sre-toolkit/skills/<skill-name>/SKILL.md` — one directory per skill, with YAML front matter (`name`, `description`) followed by the instructions. Current skills: `govcloud-readiness-review`, `incident-triage`, `prometheus-alert-authoring`, `terraform-change-review`.
- `plugins/sre-toolkit/skills/terraform-change-review/scripts/plan_risk.py` — stdlib-only analyzer for `terraform show -json` output. Prints addresses and reasons only, never attribute values. Exit codes: `0` clean, `2` threshold met, `1` bad input.
- `tests/` — pytest unit tests for helper scripts (`tests/test_plan_risk.py` loads `plan_risk.py` by path).
- `pyproject.toml` — pytest and ruff configuration.
- `release-please-config.json`, `.release-please-manifest.json` — release configuration.
- `.github/workflows/` — `ci.yml` (lint, test, plugin validation), `security.yml` (Trivy via the `platform-workflows` reusable workflow), `release-please.yml`, `dependabot-auto-merge.yml`.

## Commands

Requires Python 3.10+ and the Claude Code CLI. These are the same checks CI runs:

```bash
pip install pytest ruff==0.17.3
ruff check .                                        # lint (config in pyproject.toml)
python -m pytest -q tests                           # analyzer unit tests
claude plugin validate --strict .                   # marketplace manifest
claude plugin validate --strict plugins/sre-toolkit # plugin + skills
```

CI runs tests on Python 3.10 and 3.12, ruff on 3.12, and plugin validation on Node 22 with `npm install -g @anthropic-ai/claude-code`.

## Conventions

- **Skills are the single source of truth.** Author and edit skills only under `plugins/sre-toolkit/skills/`. Do not copy them elsewhere.
- **Keep skills portable** across Claude Code, Codex, and Gemini CLI. Do not use tool-specific variables such as `${CLAUDE_PLUGIN_ROOT}` in `SKILL.md`; reference bundled scripts by a path relative to the skill's own directory (for example `scripts/plan_risk.py`).
- Python: target `py310`, line length 120, ruff rules `E`, `F`, `W`, `I`, `UP`. `plan_risk.py` is stdlib-only; keep it that way.
- Every helper script ships with unit tests in `tests/`. Every new skill gets a row in the README's skills table.
- Skill directory names are kebab-case and match the `name` field in `SKILL.md` front matter.
- PR titles must be Conventional Commits (`feat:`, `fix:`, `docs:`, `ci:`, `chore:`, `feat!:` for breaking changes). PRs are squash-merged, so the title becomes the commit and release-please uses it to version and write `CHANGELOG.md`.
- Pin third-party GitHub Actions and reusable workflows to a full commit SHA with the version as a trailing comment (`uses: org/action@<sha> # v1.2.3`) so Dependabot can bump them.
- One concern per PR.

## Guardrails

- **Read-only by default.** Skills may inspect, validate, and plan. Anything that changes infrastructure must stop and get explicit human approval first. The Terraform skill never runs `terraform apply`, `destroy`, `import`, `state rm/mv`, or `taint`.
- **Never print secrets.** Do not echo tokens, keys, or credential files into output; redact them from summarised tool output. Do not `cat` plan JSON into the transcript.
- **Be honest about verification.** Never report that something was tested or validated unless the command actually ran and passed.
- **No secrets in the repo.** No tokens, keys, account/subscription/tenant IDs, or internal hostnames in examples or test fixtures; use obvious placeholders.
- Do not commit `tfplan` or `tfplan.json` (both are gitignored).
- Report security issues privately per `SECURITY.md`, never in a public issue.
- **Generated agent files.** `AGENTS.md`, `CLAUDE.md`, and `.gemini/settings.json` at the repo root are generated by Ruler from `.ruler/`. Edit `.ruler/AGENTS.md`, then run `npx @intellectronica/ruler@0.3.46 apply`. Never hand-edit the generated files.

## Definition of done

- `ruff check .` passes.
- `python -m pytest -q tests` passes.
- `claude plugin validate --strict .` and `claude plugin validate --strict plugins/sre-toolkit` pass.
- New or changed helper scripts have tests; README skills table and docs are updated if behaviour, inputs, or outputs changed.
- No secrets, account/subscription/tenant IDs, or internal hostnames in the diff.
- PR title is a Conventional Commit, breaking changes are marked with `!` and explained, and the PR template's "How it was validated" lists the commands run and their results.
